# 自研代理面板 — 需求分析文档（PRD）

> 版本：v0.1 草案
> 日期：2026-09-03
> 状态：待评审
> 定位：替代 Remnawave，面向「管理员自用 + 邀请制开放给他人」的代理节点编排面板

---

## 1. 背景与动机

### 1.1 为什么不用 Remnawave

现有 Remnawave 面板在使用中暴露的问题（均为实测踩坑，见 `/opt/data/workspace/knowledge/RECENT-HANDOFF.md`）：

| 痛点 | Remnawave 表现 | 期望 |
|---|---|---|
| 配置模型复杂 | profile / inbound / host / internal_squad / external_squad 五层概念 | 节点 → 入站 → 用户组，三层即可 |
| 模板黑盒 | 改配置要清 Redis 缓存、重启后端才生效 | 配置变更即时推送 |
| 一机一容器 | 一台机器 = 一个 node = 一个 profile = 一个容器 | 一台机器 = 一个 agent + 一个 sing-box，挂 N 个入站 |
| 多节点共享模板打架 | 同模板跨节点复用导致 target 失效连坐 | 每个入站独立、可独立落地 |
| 内核锁定 xray | 官方仅 xray，sing-box 需 fork | 原生支持 sing-box |
| 兼容坑 | xray 26.7.11+ minClientVer 拒绝 mihomo | 面板管理 minClientVer，一键下发 |
| 数据库脆弱 | 直接改 DB 易出问题、无事务保护 | 统一走 API + 事务 |

### 1.2 项目目标

做一个**自托管、可控、面向代理节点编排**的面板，核心价值：

1. **图形化节点编排**：在画布上拖拽「入站 → 中转 → 出站」，所见即所得生成节点配置。
2. **一机多入站**：一台服务器一个 sing-box 内核，同时承载多个协议/多个用途的入站（入口、落地、中转）。
3. **邀请制多用户**：管理员邀请码控制注册，非公开注册；用户自助管理自己的订阅。
4. **多订阅多模板**：一个用户可创建多个订阅链接，每个订阅绑定不同模板和节点组。

## 2. 用户与角色

### 2.1 角色定义

| 角色 | 权限 |
|---|---|
| **超级管理员（owner）** | 所有权限：节点、入站、拓扑、用户、邀请码、模板、系统设置 |
| **管理员（admin）** | 节点/入站/拓扑/用户管理，不含系统级设置 |
| **普通用户（user）** | 仅管理自己的订阅：创建订阅、选模板、选节点组、查看流量 |

> MVP 阶段先做 owner + user 两级，admin 留待后续。

### 2.2 用户故事（核心）

- **作为 owner**，我要在画布上拖拽出一个「reality 入口 + ss 落地」的拓扑，点保存后自动下发到对应服务器，无需手写 JSON。
- **作为 owner**，我要在一台机器上同时挂 reality 入口和 ss 落地入站，用同一个 sing-box 内核跑，不用开多个容器。
- **作为 owner**，我要把外部机房的节点（非 Coxpanel 管理）以静态参数加入节点池，并只给指定用户组使用。
- **作为 owner**，我要生成邀请码，控制谁能注册。
- **作为 user**，我凭邀请码注册后，创建自己的订阅链接（选 mihomo/sing-box 格式 + 选节点组），拿到可直接导入客户端的 URL。
- **作为 user**，我在面板上调整某节点的参数（名称/排序/分组），刷新订阅后所有设备自动同步，无需逐设备重复配置。

## 3. 功能需求

### 3.1 节点管理（Node）

- 节点分两种类型：
  - **受管节点（managed）**：Coxpanel 部署 agent 管理，支持拓扑编排、心跳、精确流量统计。
  - **外部节点（external）**：非 Coxpanel 管理的机器，无 agent，管理员手动填完整协议参数，仅作为订阅条目加入节点池（对应 Remnawave 的 external squad）。
- 受管节点记录：名称、公网 IP、EasyTier 内网 IP、SSH 信息（首次部署用）、核心版本、在线状态、流量统计。
- 受管节点与入站是 **1:N** 关系（一台机器多个入站）。
- 外部节点记录：名称 + 完整静态协议参数（协议/server/端口/UUID/SNI/Reality 公钥…），无拓扑、无心跳、无流量。
- 节点状态（受管节点）：在线/离线/维护中；外部节点无状态。
- 节点心跳：受管 agent 定时上报 CPU/内存/流量/在线用户数。

### 3.2 入站管理（Inbound）

- 入站类型（首期）：**VLESS-Reality**、**Shadowsocks（2022-blake3）**、**Hysteria2**。
- 每个入站独立配置：监听地址、端口、协议参数、TLS/Reality 参数（含 minClientVer 默认管理）、SNI/target。
- 入站有三种角色：
  - **入口（entry）**：客户端直连的节点。
  - **落地（landing）**：只给其他入口中转流量用，不直接暴露给客户端。
  - **中转（relay）**：既是落地又是下一跳入口。

### 3.3 拓扑编排（核心差异化功能）

- **画布**：React Flow，节点卡片 = 入站/出站，连线 = 流量路径。
- **翻译引擎**：画布图 → sing-box 配置（inbounds + outbounds + route.rules）。
- **实时校验**：保存时后端做 `sing-box check` 等价校验，不合法不推送。
- **下发**：校验通过 → agent 拉取/接收 → 原子写入 → 生效。

### 3.4 订阅管理（Subscription）

- 一个用户可创建**多个订阅**。
- 每个订阅：名称 + 客户端格式（mihomo YAML / sing-box JSON / base64 / v2rayN）+ 节点组选择 + 模板选择。
- 订阅 URL：`https://<domain>/sub/<token>`，token 唯一、可重置。

### 3.5 邀请制注册

- 管理员生成邀请码（可设：可用次数、有效期、绑定的节点组权限）。
- 用户凭邀请码注册，必填「用户名 + 密码 + 邮箱」（邮箱用于找回密码/通知）。
- 无邀请码无法注册（严格邀请制）；邮箱通过管理员配置的 SMTP 发送验证/通知邮件。

### 3.6 模板管理（Template）

- 模板 = 订阅生成的输出格式定义（区别于 Remnawave 的「配置模板」，这里模板只影响客户端订阅内容，不影响节点运行配置）。
- 内置模板：mihomo、sing-box、base64、v2rayN。
- 可自定义模板变量。

### 3.7 用户节点覆写（Node Override）⭐ 核心差异化

**目标**：用户在服务端调整节点参数后，任何设备「刷新订阅」即同步，无需逐设备重复配置。

- 用户对订阅内的每个节点可做**参数覆写**：
  - 显示名称、排序、图标
  - 协议参数：SNI / serverName、端口、fingerprint、flow、Reality（publicKey/shortId/spiderX）、Hy2（obfs）、SS（method/password）
  - 客户端归属：proxy-group 分组、规则匹配
- 覆写**持久化在服务端**，随订阅 URL 下发。
- 覆写优先级：**用户覆写 > 管理员模板默认值**。
- 用户刷订阅 = 全设备同步，本地客户端零重复配置。

### 3.8 流量统计

- 节点级 + 用户级流量统计。
- 用户可设流量上限、到期时间。
- 用量展示（总量/今日/近 7 天）。

## 4. 非功能需求

| 项 | 要求 |
|---|---|
| 性能 | 单面板支撑 100+ 节点、10000+ 用户（MVP 阶段 20 节点、500 用户即可） |
| 可靠性 | 配置下发失败可回滚；agent 与面板断连不影响已生效配置 |
| 安全 | 密钥加密存储；API 鉴权；邀请码防爆破；面板不存用户明文密码 |
| 可维护 | 全 Go 栈（后端 + agent）；配置 schema 类型安全（内嵌 sing-box option）；日志完整 |
| 部署 | 面板 Docker 化；agent 单二进制 |

## 5. 范围界定

### 5.1 MVP（第一阶段，P1）

- 节点 CRUD + agent 部署 + 心跳
- 入站 CRUD（reality / ss / hy2）
- 拓扑画布（基础：入站 → 出站 两级连线）
- 用户注册（邀请码）+ 登录
- 订阅生成（mihomo / sing-box 两格式）+ 多订阅
- 流量统计（基础）

### 5.2 第二阶段（P2）

- 拓扑高级：多级中转链（入口 → 中转 → 落地）
- 模板自定义
- 用量告警、到期通知
- 流量图表（ECharts）

### 5.3 第三阶段（P3）

- 多落地负载均衡
- 支付/计费（如需商业化）
- 客户端配置一键导入
- Telegram Bot 通知

### 5.4 明确不做（首期）

- 支付系统
- 多语言完整支持（先中文）
- 移动端 App

## 6. 待确认的开放问题

1. **项目名称**：**Coxpanel**（已定）。
2. **部署位置**：**NAS 容器**测试（面板 + agent 均容器化；agent 后续可直接部署宿主机，首期不做环境配置）。
3. **公网域名**：fuvia.net 二级域名（已定，建议 `coxpanel.fuvia.net`；CF zone 已确认可管理，DNS 记录创建在部署阶段做）。
4. **用户认证**：邮箱 + 邀请码注册，用户填「用户名 + 密码 + 邮箱」；SMTP 用 fuvia.net 自建邮局。
5. **Agent 语言**：Go（全 Go 栈，见 TECH-DESIGN）。
6. **是否迁移 Remnawave 数据**：**不迁移**，全新开始。
7. **开源发布**：项目将上传 GitHub，代码仓库不包含任何密钥（密钥只存 NAS `/opt/data/.env`）。
